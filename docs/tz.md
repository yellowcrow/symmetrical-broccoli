# Техническое задание: Todo List приложение

## 1. Общее описание и цель

### 1.1 Описание проекта
Разработать веб-приложение для управления списком задач (Todo List) с использованием современного технологического стека: React, TypeScript, Redux Toolkit и Tailwind CSS.

### 1.2 Цель проекта
Создать функциональное и удобное приложение, позволяющее пользователям эффективно управлять своими задачами: добавлять, редактировать, удалять, отмечать как выполненные, а также фильтровать и упорядочивать их.

### 1.3 Технологический стек
- **Vite** - инструмент сборки и dev-сервер
- **React 18+** - библиотека для построения UI
- **TypeScript** - статическая типизация
- **Redux Toolkit** - управление состоянием приложения
- **Tailwind CSS** - утилитарный CSS-фреймворк для стилизации

## 2. Юзер-кейсы

### UC-1: Просмотр списка задач

**Актёр:** Пользователь

**Предусловия:** Приложение открыто в браузере

**Основной сценарий:**
1. Пользователь открывает приложение
2. Система отображает список всех задач
3. Для каждой задачи отображается:
   - Текст задачи
   - Статус выполнения (выполнена/не выполнена)
   - Кнопки управления (редактировать, удалить)

**Альтернативные сценарии:**
- A1: Если список задач пуст, отображается сообщение "Нет задач"

**Постусловия:** Пользователь видит актуальный список задач

**Критерии приёмки:**
- Все задачи отображаются в списке
- Выполненные задачи визуально отличаются от невыполненных
- Интерфейс адаптивен и корректно отображается на разных размерах экрана

---

### UC-2: Добавление новой задачи

**Актёр:** Пользователь

**Предусловия:** Приложение открыто

**Основной сценарий:**
1. Пользователь вводит текст задачи в поле ввода
2. Пользователь нажимает кнопку "Добавить" или клавишу Enter
3. Система валидирует введённые данные
4. Система добавляет новую задачу в список
5. Система очищает поле ввода
6. Система отображает обновлённый список задач

**Альтернативные сценарии:**
- A1: Если поле ввода пустое или содержит только пробелы:
  - Система не добавляет задачу
  - Система может отобразить предупреждение

**Постусловия:** Новая задача добавлена в список и отображается

**Критерии приёмки:**
- Задача добавляется при нажатии кнопки или Enter
- Пустые задачи не добавляются
- Новая задача появляется в списке
- Поле ввода очищается после добавления

---

### UC-3: Отметка задачи как выполненной

**Актёр:** Пользователь

**Предусловия:** В списке есть хотя бы одна задача

**Основной сценарий:**
1. Пользователь нажимает на чекбокс у задачи
2. Система переключает статус задачи (выполнена ↔ не выполнена)
3. Система обновляет визуальное отображение задачи

**Альтернативные сценарии:**
- A1: Если задача была выполнена, при повторном клике она становится невыполненной

**Постусловия:** Статус задачи изменён и отображён

**Критерии приёмки:**
- Клик по чекбоксу переключает статус
- Выполненные задачи визуально отличаются (зачёркнутый текст, другой цвет)
- Изменение происходит мгновенно без перезагрузки страницы

---

### UC-4: Удаление задачи

**Актёр:** Пользователь

**Предусловия:** В списке есть хотя бы одна задача

**Основной сценарий:**
1. Пользователь нажимает кнопку "Удалить" у задачи
2. Система удаляет задачу из списка
3. Система обновляет отображение списка

**Альтернативные сценарии:**
- Нет

**Постусловия:** Задача удалена из списка

**Критерии приёмки:**
- Задача удаляется при клике на кнопку удаления
- Удаление происходит мгновенно
- После удаления задача не отображается в списке

---

### UC-5: Редактирование задачи (опционально)

**Актёр:** Пользователь

**Предусловия:** В списке есть хотя бы одна задача

**Основной сценарий:**
1. Пользователь нажимает кнопку "Редактировать" у задачи
2. Система переводит задачу в режим редактирования (inline или в модальном окне)
3. Пользователь изменяет текст задачи
4. Пользователь подтверждает изменения (Enter или кнопка "Сохранить")
5. Система валидирует введённые данные
6. Система обновляет текст задачи
7. Система выходит из режима редактирования

**Альтернативные сценарии:**
- A1: Пользователь отменяет редактирование (Esc или кнопка "Отмена"):
  - Система не сохраняет изменения
  - Система выходит из режима редактирования
- A2: Если новый текст пустой:
  - Система не сохраняет изменения
  - Система может отобразить предупреждение

**Постусловия:** Текст задачи обновлён или остался без изменений

**Критерии приёмки:**
- Можно войти в режим редактирования
- Изменения сохраняются при подтверждении
- Изменения отменяются при нажатии Esc или "Отмена"
- Пустой текст не сохраняется

---

### UC-6: Фильтрация задач по статусу (опционально)

**Актёр:** Пользователь

**Предусловия:** В списке есть задачи с разными статусами

**Основной сценарий:**
1. Пользователь выбирает фильтр ("Все", "Активные", "Выполненные")
2. Система фильтрует список задач согласно выбранному критерию
3. Система отображает отфильтрованный список

**Альтернативные сценарии:**
- Нет

**Постусловия:** Отображаются только задачи, соответствующие фильтру

**Критерии приёмки:**
- Фильтр "Все" показывает все задачи
- Фильтр "Активные" показывает только невыполненные задачи
- Фильтр "Выполненные" показывает только выполненные задачи
- Активный фильтр визуально выделен
- Счётчик задач соответствует активному фильтру

---

### UC-7: Изменение порядка задач перетаскиванием (опционально)

**Актёр:** Пользователь

**Предусловия:** В списке есть минимум две задачи

**Основной сценарий:**
1. Пользователь начинает перетаскивание задачи (drag)
2. Система визуально показывает процесс перетаскивания
3. Пользователь перемещает задачу на новое место
4. Пользователь отпускает задачу (drop)
5. Система обновляет порядок задач в списке
6. Система сохраняет новый порядок

**Альтернативные сценарии:**
- A1: Пользователь отменяет перетаскивание (отпускает вне области списка):
  - Система возвращает задачу на исходное место

**Постусловия:** Порядок задач изменён согласно действиям пользователя

**Критерии приёмки:**
- Задачи можно перетаскивать мышью
- Визуальная обратная связь при перетаскивании
- Новый порядок сохраняется
- Интерфейс работает плавно без лагов

---

### UC-8: Сохранение задач в localStorage (опционально)

**Актёр:** Система

**Предусловия:** Пользователь выполнил любое действие с задачами

**Основной сценарий:**
1. Пользователь добавляет/изменяет/удаляет задачу
2. Система автоматически сохраняет текущее состояние в localStorage
3. Пользователь закрывает браузер
4. Пользователь открывает приложение снова
5. Система загружает данные из localStorage
6. Система восстанавливает список задач

**Альтернативные сценарии:**
- A1: Если localStorage недоступен:
  - Система работает в режиме in-memory
  - Данные теряются при закрытии браузера

**Постусловия:** Данные сохранены и доступны при следующем открытии

**Критерии приёмки:**
- Все изменения автоматически сохраняются в localStorage
- При перезагрузке страницы данные восстанавливаются
- Порядок задач сохраняется
- Статусы задач сохраняются

## 3. Нефункциональные требования

### 3.1 Производительность
- Приложение должно загружаться менее чем за 2 секунды
- Операции с задачами должны выполняться мгновенно (< 100ms)

### 3.2 Совместимость
- Поддержка современных браузеров (Chrome, Firefox, Safari, Edge)
- Последние 2 версии каждого браузера

### 3.3 Адаптивность
- Корректное отображение на десктопах (1920x1080 и выше)
- Корректное отображение на планшетах (768x1024)
- Корректное отображение на мобильных устройствах (375x667 и выше)

### 3.4 Доступность
- Использование семантических HTML-тегов
- Поддержка навигации с клавиатуры
- ARIA-атрибуты для важных элементов

### 3.5 Качество кода
- Использование TypeScript для статической типизации
- Соблюдение best practices React и Redux Toolkit
- Понятная структура проекта и именование файлов

## 4. Ограничения и допущения

### 4.1 Ограничения
- Приложение работает только в браузере (нет нативных мобильных приложений)
- Нет серверной части (все данные хранятся локально)
- Нет аутентификации и системы пользователей

### 4.2 Допущения
- Пользователь имеет современный браузер с поддержкой ES6+
- Пользователь имеет включённый JavaScript
- localStorage доступен и не заблокирован настройками браузера
